# 官方文档library.dox文档总结

PipeWire 是一个音频和媒体处理框架，其核心库由两个主要部分组成：

基于图的媒体处理引擎和异步 IPC 机制，用于在不同进程中操作和检查媒体图。

以下是文档的翻译总结，保留原文中的专有名词术语：

### 核心组成
1. **媒体处理引擎**：实现了一个基于图的处理引擎，处理音频和其他媒体数据。
2. **异步 IPC 机制**：受 Wayland 启发，通过对象和方法/事件的设计，允许客户端与 PipeWire daemon 通信，操作远程进程中的媒体图。

通常有一个 PipeWire daemon 维护全局图，客户端通过 IPC 操作此图。

### 设计原则
- **面向对象的异步协议**：所有请求和回复都是对象上的方法调用。对象通过唯一 ID 标识，每个对象实现特定接口，消息分为客户端发往服务器的 **method** 和服务器发往客户端的 **event**。
- **消息编码**：使用 **SPA_POD** 编码复杂对象，确保类型正确。
- **事件机制**：服务器会广播状态变化，客户端需监听并缓存这些变化，无需主动查询服务器状态。
- **Registry 对象**：用于广播全局对象的存在及其状态变化，客户端可绑定对象以获取状态或调用方法。
- **插件架构**：支持动态添加或移除功能，插件可改变 PipeWire 的行为或功能。

### 版本控制
- 每个接口有版本号，通过 **registry global event** 公布支持的最高版本。
- 客户端绑定对象时指定接口版本，服务器需适配客户端版本。
- 版本号仅在新增方法或事件时增加，方法或事件不会被移除或更改。

### 代理与资源
- 客户端连接 PipeWire daemon 时，创建 ID 为 0 的 **struct pw_proxy**，关联 **struct pw_core** 接口。
- 服务器端对应一个 ID 为 0 的 **struct pw_resource**。客户端通过 **proxy** 发送消息，服务器通过 **resource** 响应。
- 消息在客户端和服务器间透明传递，客户端需在资源 ID 失效时销毁对应的 **proxy**。

### 主要接口
1. **struct pw_loop**：抽象的 `poll(2)` 循环，支持以下实现：
   - **struct pw_main_loop**：运行和停止 **pw_loop**。
   - **struct pw_thread_loop**：在单独线程中运行 **pw_loop**，提供线程同步功能。
   - **struct pw_data_loop**：在实时线程中运行 **pw_loop**，提供实时处理支持。
2. **struct pw_context**：管理 PipeWire 资源，包括主循环、加载模块、处理图和远程代理。
3. **struct pw_core**：与远程 PipeWire 实例通信的代理，支持错误接收和请求同步。
4. **struct pw_registry**：广播服务器上可用对象及状态变化，支持绑定对象。
5. **struct pw_module**：表示可加载模块，提供新对象或策略。
6. **struct pw_factory**：创建其他对象的工厂代理。
7. **struct pw_device**：模拟硬件或软件设备，可创建节点或其他设备。
8. **struct pw_node**：处理图中的节点，包含输入/输出端口，可连接形成图。
9. **struct pw_port**：节点的输入或输出端口，可链接形成处理图。
10. **struct pw_link**：连接输入和输出端口，协商格式和缓冲区，支持多端口链接和缓冲区管理。

### 高级辅助对象
1. **struct pw_filter**：实现处理过滤器，类似于 JACK 客户端，可加入 PipeWire 图。
2. **struct pw_stream**：简化播放或捕获客户端的实现，处理格式转换和缓冲区大小，类似于 Core Audio AudioQueue 或 PulseAudio 流。

### 安全性
- **连接方式**：默认使用命名套接字，沙盒客户端可通过 portal 获取连接套接字。
- **权限控制**：对象具有 READ、WRITE、EXECUTE 和 METADATA 权限，客户端需相应权限才能查看、修改或执行对象操作。
- **权限管理**：客户端可通过 portal 或会话管理器分配权限，权限一旦移除无法恢复。
- **数据共享**：使用 **memfd** 或 **DMA-BUF** 共享媒体数据，确保客户端无法访问未授权数据。

### 实现
PipeWire 提供 API 用于实现服务器端对象，支持构建自定义媒体图。

### 错误处理
- 函数返回 NULL 并设置 **errno**，或返回负数错误码（来自 SPA 插件库）。
- 异步操作返回正数错误码，可通过 **SPA_RESULT_IS_ASYNC()** 判断，**SPA_RESULT_ASYNC_SEQ()** 获取唯一序列号。
- 异步操作完成通过回调通知，序列号用于匹配操作。

总结来说，PipeWire 提供了一个灵活、模块化的媒体处理框架，通过异步 IPC 和面向对象的协议，支持客户端与服务器高效交互，适用于音频和其他媒体处理场景。
